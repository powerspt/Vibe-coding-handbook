🎬 도입 (5분)

할 말의 흐름
- "바이브 코딩(vibe coding)은 코드를 직접 쓰는 대신, 사람 말로 원하는 걸 설명하면 AI가 코드를 대신 써주는 방식입니다. 2025년 초에 등장한 용어인데, 1년 만에 비전공자도 앱을 만드는 시대가 됐습니다."
- "여러분은 요리 레시피를 짜는 사람이고, AI는 그 레시피대로 요리하는 주방장이라고 생각하세요. 칼질을 잘하는 게 아니라 레시피를 명확하게 쓰는 게 오늘의 핵심입니다."
- 오늘의 약속: "강의가 끝나면, 여러분 각자가 '한 줄 방명록' 같은 작동하는 웹앱을 직접 만들어볼 겁니다. 코드 한 줄 몰라도 됩니다."

팁: 가능하면 완성된 예시 앱(방명록)을 미리 띄워두고 "이게 오늘 여러분이 만들 결과물입니다"라고 보여주면 몰입도가 확 올라갑니다.

🌐 파트 1 — 웹앱은 어떻게 동작하는가 (10분)

비전공자에게는 비유로 설명하는 게 가장 효과적입니다.

① 웹앱의 동작 = 식당

  • 손님(사용자/브라우저) 이 주문(요청)을 한다 → 주방(서버) 이 요리(처리)를 한다 → 음식(응답)을 내준다.
  • 우리가 주소창에 사이트를 입력하면, 내 컴퓨터가 멀리 있는 서버에 "이 페이지 주세요"라고 요청하고, 서버가 화면을 보내주는 것.
  • 홀(프론트엔드): 손님 눈에 보이는 부분 — 메뉴판, 테이블, 인테리어.
  • 주방(백엔드): 손님 눈에 안 보이지만 실제로 일이 돌아가는 곳 — 데이터 처리, 저장.

② 화면을 이루는 3가지 = 집 짓기

요소 역할 비유
HTML 구조 / 뼈대 벽, 방, 문 (어디에 뭐가 있나)
CSS 꾸밈 / 디자인 벽지, 색깔, 가구 배치 (예뻐 보이게)
JavaScript 동작 / 기능 전기·스위치 (버튼 누르면 불이 켜진다)
💬

강조 멘트: "여러분은 이걸 직접 안 짭니다. AI에게 '이런 집을 지어줘'라고 설명만 하면 됩니다. 다만 HTML/CSS/JS가 각각 뭘 하는지 알면, AI에게 '글씨 색만 바꿔줘(CSS)', '버튼 동작을 바꿔줘(JS)'처럼 정확히 요청할 수 있습니다."

③ 데이터는 어디에 사는가? (파트 2로 가는 다리)

  • 주방에는 냉장고/창고(데이터베이스) 가 있다 → 손님이 다 가도 재료는 남아있다.
  • "그럼 남는 정보와 사라지는 정보가 있다는 건데... 그게 다음 파트의 핵심입니다."

💾 파트 2 — 단순 HTML vs 저장·상호작용의 차이 (8분)

이 파트가 오늘 강의에서 개념적으로 가장 중요합니다. 앱의 난이도를 결정하는 핵심이기 때문입니다. 3단계 모델로 설명하세요.

1단계 — 정적 페이지 (단순 HTML) = 📄 종이 포스터

  • 보기만 한다. 글씨와 그림이 박혀 있다.
  • 새로고침해도 똑같다. 내가 뭘 입력할 수 없다.
  • 예: 가게 안내문, 회사 소개 페이지.

2단계 — 상호작용 (저장 X) = 🖍️ 화이트보드

  • 내가 글씨를 쓰면 화면에 나타난다. 버튼을 누르면 반응한다.
  • 그런데 새로고침(또는 창을 닫으면) 다 사라진다. 화이트보드를 지운 것과 같다.
  • 예: 계산기, 입력하면 즉시 결과가 바뀌는 화면.

3단계 — 저장 (Storage) = 📒 노트·장부

  • 입력한 내용이 닫았다 다시 열어도 남아있다.
  • 여기서 또 두 갈래로 나뉩니다:
  • 내 기기에만 저장 (브라우저 저장 / localStorage) = 내 책상 위 개인 노트. 다른 사람·다른 기기에서는 안 보임.
  • 진짜 저장 (데이터베이스) = 모두가 함께 보는 공용 장부. 다른 사람도, 폰에서도 같은 내용을 본다.
💬

핵심 멘트 (꼭 하세요):
"'저장'과 '여러 사람이 함께'가 필요한 순간, 난이도가 한 단계 올라갑니다. 그래서 앱을 만들기 전에 반드시 이 질문에 답해야 합니다 —
'이 정보가 새로고침해도 남아야 하나요?'
'다른 사람·다른 기기에서도 보여야 하나요?'
이 답에 따라 AI에게 시킬 내용이 완전히 달라집니다."

📌
이 질문은 파트 4(과업지시서 체크리스트)의 핵심 항목으로 다시 등장합니다.

⚠️ 파트 3 — 바이브 코딩 시 고려해야 할 점 (8분)

"AI에게 잘 시키는 법"의 원칙들입니다. '성실한 신입 직원' 비유로 묶으면 외우기 쉽습니다.

  1. AI는 시키는 대로 하는 성실한 신입이다.
    똑똑하지만 눈치는 없습니다. 모호하게 말하면 자기 마음대로 해석합니다. → 구체적으로. ("예쁘게" ❌ → "버튼은 파란색, 모서리는 둥글게" ⭕)

  2. 한 번에 다 만들지 말고, 작게 쪼개서 한 기능씩.
    처음부터 10가지 기능을 한 프롬프트에 다 넣으면 엉킵니다. → 화면 먼저 → 입력 기능 → 저장 기능 순서로 단계별 추가.

  3. 결과를 믿지 말고 직접 눌러보며 확인한다.
    "되겠지" 하지 말고 클릭해 봅니다. 안 되면 "이렇게 눌렀더니 이런 에러가 떴어" 라고 화면/메시지를 그대로 전달하세요. AI는 그걸 보고 고칩니다.

  4. 막히면 같은 말을 반복하지 말 것.
    똑같은 요청을 3번 해도 똑같이 막힙니다. → 표현을 바꾸거나, 화면을 캡처해 붙이거나, "다른 방법으로 해줘"라고 접근을 바꾸세요.

  5. 민감 정보는 절대 넣지 않는다.
    비밀번호, 카드번호, 실명+전화번호 같은 개인정보를 프롬프트나 앱에 넣지 마세요. 특히 만든 앱을 인터넷에 공개로 배포할 때 주의. (무료 플랫폼은 입력 내용을 학습에 쓸 수 있습니다.)

  6. 다 이해 못 해도 괜찮지만, 큰 흐름은 파악한다.
    "왜 이렇게 했어?"라고 AI에게 물어보며 조금씩 익히세요. 완벽히 이해할 필요는 없지만, 내 앱이 데이터를 어디에 저장하는지 정도는 알고 있어야 합니다.

  7. 기대치 관리.
    간단한 도구·프로토타입에는 정말 강력합니다. 하지만 기능이 많아지고 복잡해지면 한계가 옵니다. → "작고 쓸모 있는 것부터" 시작하세요.

📋 파트 4 — 과업지시서 작성 전 체크리스트 (10분)

"AI에게 시키기 전에, 내가 뭘 원하는지부터 정리한다." 육하원칙처럼 6가지 + 참고자료로 정리하면 비전공자도 빠짐없이 쓸 수 있습니다. (빈 템플릿은 부록 A 참고)

# 질문 정해야 할 것 예시
① 무엇을 / 왜? (목적) 한 문장으로 정의 "우리 모임 회비를 자동으로 나눠 계산하는 앱"
② 누가 쓰나? (사용자·환경) 나만? 여럿? PC? 폰? "모임 회원 10명이 각자 폰으로"
③ 무슨 기능? (기능 목록 + 우선순위) 꼭 필요한 것(MVP) vs 있으면 좋은 것 (필수) 금액 입력·자동 분배 / (나중에) 정산 내역 저장
④ 어떻게 생겼나? (화면 구성) 화면 몇 개, 뭐가 보이나 "한 화면. 위에 입력칸, 아래에 결과"
⑤ 어떤 정보를 다루나? (데이터·저장) 입력/표시할 정보, 저장 필요 여부 "이름·금액. 다음에 열어도 남아야 함 → 저장 필요"
⑥ 제약·기타 무료, 한글, 로그인 여부 등 "무료, 한글, 로그인 없이"
⭐ 참고할 예시 "이 사이트/앱처럼" 1~2개 "더치페이 앱 ○○처럼 깔끔하게"
💬

강조 멘트: "특히 ⑤번 — 저장이 필요한가? — 이게 파트 2에서 본 그 질문입니다. 이거 하나만 명확히 정해도 결과물이 완전히 달라집니다."

실습 연결: "지금 종이/메모장을 꺼내서, 여러분이 만들 앱을 이 6칸에 채워보세요. 이게 곧 여러분의 첫 프롬프트가 됩니다." (이 자리에서 2~3분 직접 쓰게 하면 실습 전환이 매끄럽습니다.)

🛠️ 파트 5 — 첫 웹앱 만들기 (Step by Step 시연, 12분)

예제: "한 줄 방명록" — 저장의 차이를 가장 잘 보여주는 예제입니다.
(대안: 모임 회비 정산기 / 간단 투표 — 부록 B)

화면에 띄워놓고 실시간으로 같이 만드는 모습을 보여주세요.

Step 1. 아이디어 → 과업지시서 (1분)

💬

"방명록을 만든다. 방문자가 한 줄 메시지를 남기면 화면에 목록으로 쌓인다. 새로고침해도 남아야 한다. 무료·한글·로그인 없음."

Step 2. 플랫폼 열기 (1분)

  • Google AI Studio(aistudio.google.com) 또는 claude.ai 접속. 새 프로젝트 시작.

Step 3. 첫 프롬프트 입력 (3분)

한 번에 길게 쓰지 말고, 핵심부터 입력합니다.

프롬프트
간단한 방명록 웹앱을 만들어줘.
- 방문자가 이름과 한 줄 메시지를 입력하고 '남기기' 버튼을 누르면
  아래 목록에 추가돼.
- 한글, 깔끔한 디자인, 로그인 없이.
- 모바일에서도 잘 보이게.

→ 미리보기에서 입력·버튼이 작동하는 화면이 나옵니다. (= 파트 2의 2단계, 상호작용)

Step 4. 직접 눌러서 테스트 (1분)

  • 이름·메시지 넣고 버튼 클릭 → 목록에 추가되는지 확인.
  • 여기서 새로고침 → 사라짐을 보여주며: "보세요, 아직 화이트보드 단계입니다."

Step 5. 저장 기능 추가 (3분) ← 오늘의 하이라이트

프롬프트
지금은 새로고침하면 글이 사라져.
새로고침해도 남아있도록 저장 기능을 추가해줘.

→ 다시 새로고침해도 글이 남는 걸 보여줍니다. (= 파트 2의 3단계, 저장)
- (심화) "다른 사람도 같은 글을 보게 하려면?" → 데이터베이스 연동이 필요하다고 짚어주기. (시간 되면 Google AI Studio의 Firebase 연동 언급)

Step 6. 다듬기 & 마무리 (2분)

프롬프트
글이 최신순으로 위에 오게 해줘.
그리고 글마다 작성 시간을 같이 보여줘.
  • (원하면) 배포/공유 버튼으로 인터넷 주소 만들기까지 시연.

Step 7. 정리

💬

"보셨죠? ① 한 문장으로 시작 → ② 작동하는 화면 → ③ 한 기능씩 추가 → ④ 눌러서 확인. 이게 바이브 코딩의 전부입니다."

🆓 파트 6 — 무료 플랫폼 추천 + 실습 안내 (7분)

6-1. 빌드(앱 만들기)용 — 크레딧 걱정 적은 순

플랫폼 특징 추천 상황
Google AI Studio
(aistudio.google.com)		 UI 영구 무료, 신용카드·크레딧 없음. 구글 계정만 있으면 됨. 무료는 Flash 모델 기준(초보 실습엔 충분). ⭐ 단체 동시 실습에 최적. 중간에 막힐 걱정이 가장 적음
Claude
(claude.ai)		 무료, 미리보기 즉시. '정적→상호작용→저장' 차이를 한 곳에서 보여주기 좋음 ⭐ 개념 시연 + 가벼운 첫 앱 만들기
Bolt.new 아이디어→화면까지 가장 빠름. 단, 무료 토큰이 빨리 소진됨 빠르게 결과 뽑아보기 (소진 주의 안내)
Base44 한 문장으로 DB 있는 앱까지 생성. 무료 플랜이 후한 편 좀 더 본격적인 앱
Lovable 입문자에게 가장 친절한 대화형 빌더 무료 크레딧이 하루 약 5회로 적어 단체 실습엔 빠듯
Replit 브라우저 안 풀 개발환경 빌드는 무료지만 무료 퍼블리싱은 1개·30일 제한(아래 참고)

6-2. 퍼블리싱(인터넷에 공개)용 — "정적 vs 백엔드"로 갈린다

💡

핵심: 앱을 만드는 건 거의 다 무료다. 인터넷에 올릴 때 비용이 갈리는데, 그 기준이 바로 파트 2에서 본 구분이다 —
① 혼자 도는 정적 앱 (브라우저 저장 localStorage 포함) → 영구 무료로 공개 가능
② 서버에서 데이터를 공유하는 백엔드 앱 (모두가 같은 글을 보는 방명록 등) → 한도가 생김

① 정적 앱이면 (대부분의 입문 앱): 전용 정적 호스팅이 가장 견고. 진짜 영구 무료·카드 불필요.
- Netlify — 폴더를 드래그&드롭(Netlify Drop)하면 끝. 입문자에게 가장 쉬움.
- Cloudflare Pages / Vercel(Hobby) / GitHub Pages — 모두 무료. (GitHub Pages는 계정·레포 필요)
- 워크플로: 아무 데서나 만들기 → 코드 받기 → Netlify에 드래그 → 공개 URL. 플랫폼 크레딧과 무관해 단체 실습에 사고가 가장 적음.

② 백엔드·공용 DB가 필요하면:

플랫폼 무료 퍼블리싱 함정
Google AI Studio → Cloud Run 첫 2개 앱 무료, 카드 X (2026 I/O부터) 3개째부터·실행 중 API 초과·확장 시 결제
Base44 / Lovable 자체 도메인으로 공개(브랜딩 표시) 빌드 크레딧 한도 (Lovable 하루 5회)
Bolt.new → Netlify 코드 내보내 Netlify에 무료 배포 빌드 토큰 빨리 소진
Replit 무료는 1개 앱·30일 후 만료(재배포 가능)·정적만 백엔드 배포는 유료(autoscale $1~, VM $20~)
📌

Google AI Studio 결제 오해 정정: 빌드는 물론 첫 앱 공개도 카드 없이 무료입니다(2026년 5월부터 첫 2개 무료). 수강생이 각자 1개씩 공개하는 실습엔 무료로 충분.

수업용 결론:
- 만들기는 Google AI Studio 또는 Claude로 시작 (무료·안 끊김).
- "즉시 자체 URL로 공개"의 매끄러움을 원하면 → Base44 또는 Google AI Studio(첫 앱 무료·카드 X).
- 대부분 입문 앱은 정적이므로, 가장 사고 없는 공개는 → Netlify / Cloudflare Pages에 무료 배포.

실습 안내 (마무리)

  1. 파트 4에서 채운 과업지시서 6칸을 그대로 첫 프롬프트로 만들기.
  2. 파트 5의 7단계 흐름대로 진행 (한 기능씩!).
  3. 막히면 → 화면 캡처해서 AI에게 그대로 보여주기.
  4. 추천 첫 과제는 부록 B, 복사용 프롬프트는 부록 C 참고.
  5. (원하면) 인터넷 공개까지 → 정적 앱은 Netlify 드래그&드롭, 백엔드 앱은 AI Studio 첫 앱 무료 배포.

① 한 줄 방명록 — 오늘의 대표 실습 과제

프롬프트

프롬프트

- 이름과 한 줄 메시지를 입력해 '남기기'를 누르면 아래 목록에 추가돼.
- 최신 글이 위로 오고, 글마다 작성 시간 표시.

응용 팁(강사용): "모두가 같은 방명록을 보게 하고 싶어요"가 나오면 → 그건 백엔드·공용 DB가 필요한 경우(파트 6-2 ②). 정적 버전(내 기기에만 저장)으로 먼저 완성한 뒤, 원하는 분만 "다른 사람도 같은 글을 보도록 데이터베이스에 저장해줘"로 확장하게 안내하세요.

③ 간단 투표

프롬프트
간단한 투표 웹앱을 만들어줘.

- 각 보기의 현재 득표수가 막대로 보이게.
- 새로고침해도 표가 유지되게 저장 기능 추가해줘.
